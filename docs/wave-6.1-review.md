# Wave 6.1 review — browser-pane remote-frame protocol

**Verdict: APPROVE WITH CHANGES.** The implementation is faithful to spec §4 in its load-bearing structure — real generation fencing with invalidation-before-new-state, a genuine lifecycle state machine shared between desktop and tests, replace-latest depth-1 at every boundary (worker → pipe → per-WS-subscriber), one shared transport module actually extracted (device path delegates to it, wire untouched), a hardened private frame pipe (0700 dir, 0600 socket, symlink checks, timing-safe capability, one-way after auth), and server-side lease gating of input that I verified in code and tests. The gate-stabilization commit is clean: main's suite was demonstrably red before this branch (the deleted appSettings expectations reference `enableAppSnap`, which does not exist in `apps/web/src/appSettings.ts` on main), and no lint rule, tsconfig, skip, or suppression was touched; I re-ran the new tests and full typecheck in the worktree and both pass. The changes required are four MAJORs: client-controlled `origin` can dodge `markHumanControl`, the exact-`seq` input fence will reject most input on busy pages, lease/subscription cleanup leaks permanently when the desktop is unreachable at disconnect, and there is no resubscribe-snapshot on the frame channel (blank pane on static pages after reconnect).

**Axis results**

- Gate-weakening check (commit 20b571543): **PASS** (see findings 8; production-behavior changes bundled into a "fix tests" commit is a hygiene nit, not a weakening)
- Security (`/ws/browser-frames` + browser RPCs): **PASS with required changes** (findings 1, 3; no anonymous path, principal retained per subscriber, lease enforced server-side, frames unreachable without auth — verified in `browserFrameRoute.ts`, `browserPaneManager.ts`, `wsRpc.auth.test.ts`)
- Wire compat (device H.264 path): **PASS** — `encodeDeviceFrame`, route path, and subscriber priming semantics are byte/behavior-identical; `deviceFrameTransport.ts` now delegates to `BinaryFrameTransport` with `drop-until-keyframe` reproducing the old codec-config/keyframe rules; the new JSON-header envelope is browser-only
- GPL exposure: **PASS** — all new code (select shim, coordinator, transports) is house-style in-house code with Luminor-specific naming; no Waku/hunk/Zed-derived text, no copied headers. Sharp is Apache-2.0 but ships LGPL libvips prebuilds (see finding 7)

**Findings**

1. **MAJOR — client-supplied `origin:'agent'` bypasses `markHumanControl`.** `apps/server/src/wsRpc.ts:1029-1032` passes `BrowserInputDispatchRequest` (including `origin`) straight through; `apps/desktop/src/browserFrame/controller.ts:485-492` only marks human control when `origin === "human"`. Nothing produces legitimate agent input on this RPC (agent input rides the `browser_*` tool pipe), so a lease-holding GUI client claiming `agent` drives the page without bumping the human epoch — agent tools won't abort while a human interferes, exactly the arbitration §4.7 exists to protect. Fix: in the WS handler, stamp/enforce `origin: "human"` for session/loopback principals (reject or overwrite anything else); keep the field on the desktop contract for a future authenticated agent path.

2. **MAJOR — exact-sequence input fence rejects input whenever a newer frame exists.** `apps/desktop/src/browserFrame/controller.ts:67` (`request.seq !== state.seq → "stale-frame"`) compares the echoed _displayed_ seq against `session.lastFrameSeq` — the latest _produced_ frame (`controller.ts:453`). With depth-1 slots at the worker, pipe, and WS subscriber, the client's displayed frame trails production by up to ~3 frames under sustained painting, so on any animated/busy page virtually every click, key, and move is rejected until painting stops. Spec §4.2 requires rejection when identifiers no longer "match the live target" (desktop/thread/tab/generation); seq echo is provenance, not a liveness gate. Fix: fence on desktop/thread/tab/generation and accept `seq <= lastFrameSeq` within the live generation.

3. **MAJOR — lease and state-listener leak when desktop control fails during disconnect.** `browserPaneManager.disconnect()` is never called from production code (only tests — `apps/server/src/browserPane/browserPaneManager.test.ts:111`); cleanup relies solely on the `browser.subscribe` stream finalizer at `apps/server/src/wsRpc.ts:985-992`, where `Effect.promise(...)` turns a rejected `unsubscribeViewer` into a _defect_ that `Effect.orElseSucceed` does not catch, so `unsubscribeState()` never runs. Worse, `unsubscribeViewerLocked` (`browserPaneManager.ts:212-228`) removes the viewer, then `await this.control({type:"unsubscribe"...})` — which throws when the desktop is down — _before_ `releaseLeaseForClient`, leaving a lease owned by a dead `clientId` forever; every future `acquireController` for that thread returns `controller-unavailable` until server restart. Fix: register a per-connection close hook that calls `browserPaneManager.disconnect(clientId)`; release the lease before the desktop control call; make the finalizer failure-proof (`Effect.tryPromise` + `Effect.ensuring(unsubscribeState)`).

4. **MAJOR — no resubscribe-snapshot on the frame channel (spec §4.2).** `apps/server/src/browserPane/browserFrameTransport.ts` caches nothing per thread (contrast `latestKeyframe` in `deviceFrameTransport.ts`), and the desktop `subscribe()` for an already-running session (`controller.ts:200-208`) forces no paint — `webContents.invalidate()` runs only in `acquisition.start()` (`acquisition.ts:121`). A frame-WS reconnect (or second viewer) on a static page receives zero frames indefinitely. Fix: every browser JPEG is a keyframe — cache the latest encoded envelope per thread (invalidated on generation bump/desktop loss in `browserPaneManager`) and prime it via the transport's existing `initialFrames`, or force `invalidate()` whenever a new frame subscriber attaches.

5. **MINOR — `browser.controller.revoke` is a dead alias of release.** `apps/server/src/wsRpc.ts:1047-1050` routes revoke to `releaseController(clientId, …)`, so only the holder can "revoke" — the RPC can never do what its name and `BrowserControllerRevokeRequest` contract imply. Implement authorized third-party revocation (it's the natural recovery for finding 3) or delete the method from the public surface.

6. **MINOR — remote wheel input never marks human control.** `controller.ts:485-492` marks on key/insertText/mousePressed only, while the existing epoch classes include `mouseWheel` and `contextMenu` (`apps/desktop/src/browserManager.ts:1136-1143`, cited by spec §4.7 as "the same event classes that bump the epoch today"). A human scrolling the pane won't abort agent tools. Add `wheel` (not `mouseMoved`) to the marking set.

7. **MINOR — Sharp shipped into the desktop app without dependency review.** `apps/desktop/package.json:20`, `scripts/lib/desktop-platform-build-config.ts:20-24` (asarUnpack `sharp/**`, `@img/**`). The report gives no rationale vs. alternatives (`@julusian/jpeg-turbo`, or Electron's `nativeImage.toJPEG` traded against main-thread blocking), no size impact (~tens of MB of prebuilt libvips per platform), and no license handling — `@img/sharp-libvips-*` prebuilds are LGPL-3.0; the repo has no THIRD_PARTY_NOTICES mechanism at all. Document the choice and add a notices step to desktop packaging.

8. **MINOR — deleted regression test leaves `WS_REQUEST_RECONNECTED` uncovered.** Commit 20b571543 removed the only test asserting the reconnect-interrupt mapping still present at `apps/web/src/wsTransport.ts:840-849` (`rg WS_REQUEST_RECONNECTED apps/web/src/wsTransport.test.ts` → 0 hits; the retained tests cover `WS_CONNECTION_INTERRUPTED` and the retry loop only). The deletion is defensible (the test's mocked internals predate the retry loop and could not pass), but the branch should be re-covered with a test built on the current `executeRequestOnce` seam rather than dropped.

9. **MINOR — frame-WS legacy token compared with `===`.** `authorizeBrowserFrameWebSocketUpgrade` (`apps/server/src/wsRpc.ts:2389-2414`) uses plain string equality for the loopback token while the desktop pipe handshake correctly uses `Crypto.timingSafeEqual` (`framePipeServer.ts:215-218`). Parity with the pre-existing device route, and loopback-only, so low practical risk — but trivial to fix in both.

10. **MINOR — mousemove coalescing keeps the first position per frame, not the latest.** `controller.ts:460-475` returns the pending dispatch's promise for any later move sharing the displayed `(generation, seq)`, so subsequent cursor positions within a frame tick are dropped rather than replacing the pending one; the guest sees the _earliest_ position each tick. Replace-latest (dispatch newest coords after the in-flight one settles) matches the back-pressure policy used everywhere else.

**Test quality note:** the fault-injection coverage is real, not mock-on-mock — the lifecycle machine is exercised directly (`browserStreamLifecycle.test.ts`: rapid tab switches, thread closure, debugger replacement, restart), stale-session and late-command-after-destruction are tested at the actual coordinator boundary (`cdpRuntime.test.ts:151,162`), and the pipe handshake test runs a real socket. The one gap: "revokes the first on disconnect" tests `manager.disconnect()`, a path production never invokes (finding 3), so the deployed disconnect path (stream finalizer) is untested.

AgentMemory was used: `memory_smart_search` for prior browser-pane/lease/fencing regressions returned no results; nothing new was saved (findings belong to this review, not durable project facts).

## Dispositions

1. Overwrote all session and loopback feature-WebSocket input origins with `human` before manager dispatch, while retaining `origin` in the desktop contract (`apps/server/src/wsRpc.ts:203`, `apps/server/src/wsRpc.ts:1056`).
2. Changed the desktop fence to accept any sequence at or below the latest produced sequence after desktop/thread/tab/generation validation; future or missing produced sequences remain rejected (`apps/desktop/src/browserFrame/controller.ts:53`).
3. Bound RPC client IDs to the connection scope and call `browserPaneManager.disconnect` on close, moved lease release ahead of desktop unsubscribe, and replaced the stream finalizer with `Effect.tryPromise` plus `Effect.ensuring` (`apps/server/src/wsConnectionSessions.ts:38`, `apps/server/src/wsRpc.ts:211`, `apps/server/src/wsRpc.ts:2492`, `apps/server/src/browserPane/browserPaneManager.ts:215`).
4. Added a per-thread latest-envelope cache primed through `initialFrames`; manager state transitions invalidate it on identity/generation changes and desktop loss (`apps/server/src/browserPane/browserFrameTransport.ts:13`, `apps/server/src/browserPane/browserPaneManager.ts:408`, `apps/server/src/browserPane/browserPaneManager.ts:491`).
5. Implemented owner-only third-party revocation with a distinct manager operation instead of aliasing holder release (`apps/server/src/wsRpc.ts:1081`, `apps/server/src/browserPane/browserPaneManager.ts:345`).
6. Added wheel events to human-control marking while leaving mouse movement unmarked (`apps/desktop/src/browserFrame/controller.ts:123`).
7. Added root `THIRD_PARTY_NOTICES.md`, packaged it on macOS/Linux/Windows, and documented the encoder rationale and measured 34 MB checkout impact (`THIRD_PARTY_NOTICES.md:1`, `scripts/lib/desktop-platform-build-config.ts:18`, `docs/wave-6.1-report.md:274`).
8. Added a regression on the current `executeRequestOnce` replacement seam that asserts runtime disposal maps to retryable `WS_REQUEST_RECONNECTED` (`apps/web/src/wsTransport.test.ts:1425`).
9. Replaced both feature/device and browser-frame legacy token comparisons with a shared `Crypto.timingSafeEqual` helper, including unequal-length rejection coverage (`apps/server/src/wsRpc.ts:2404`, `apps/server/src/wsRpc.ts:2446`, `apps/server/src/wsRpc.ts:2458`).
10. Replaced first-position mousemove coalescing with a replace-latest drain that sends the newest queued coordinates after the in-flight move settles (`apps/desktop/src/browserFrame/controller.ts:74`, `apps/desktop/src/browserFrame/controller.ts:524`).
